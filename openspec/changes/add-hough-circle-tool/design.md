# Design

## Context

仓库从零开始，没有既有实现可复用。约束有三条：只能在标准 OpenCV + Python 依赖内实现；界面要能在普通笔记本上秒级响应滑块操作；同一套参数必须能在界面和命令行之间原样复现。行为契约见 `specs/hough-circle-tool/spec.md`，动机见 `proposal.md`。

## Goals / Non-Goals

**Goals:**

- 参数只在一处定义，界面、命令行、测试共用，避免三份默认值漂移。
- 预览与导出共用同一份绘制代码，保证"看到什么就导出什么"。
- 检测与绘制不依赖 GUI，便于用单元测试覆盖两张样例图的验收口径。

**Non-Goals:**

- 不做图像预处理流水线（自适应阈值、Hough 变体切换），保持参数集与 `cv2.HoughCircles` 一致。
- 不做视频流、批量目录处理与结果持久化。
- 不引入 PyQt / PySide 等重量级 GUI 依赖。

## Decisions

**用 `tkinter` 而不是 PyQt。** 验收机只要求能跑起来，tkinter 随官方 Python 发布，零额外安装；PyQt 需要额外 50MB 级依赖，且打包/字体配置成本更高。代价是控件外观朴素，用 `ttk` 主题缓解。

**参数收敛为 `CircleParams` 数据类。** 界面滑块、命令行参数、测试断言都从这一个数据类取默认值与字段名，新增参数时只改一处。备选方案是各处写 dict，但字段名拼错时只能在运行时暴露。

**预览用"先绘制、再等比缩放"的方式。** 直接把 `annotate()` 的输出缩放到画布尺寸，缩放只影响显示，不影响导出文件分辨率；如果反过来先缩放再检测，圆坐标会随窗口大小变化，调参结果无法复现。

**滑块用 `after` 做 150 ms 防抖。** 拖动滑块会连续触发回调，逐次检测会把界面卡住；停手后再算一次，既保持"拖动即可见"的手感，也避免重复计算。整数型参数在回调里吸附为整数，否则滑块内部的浮点值会让 `param2` 显示成 39。

**命令行与界面共用 `detector` / `annotate`，界面不做第二套逻辑。** 这样"界面能复现的结果，命令行一定能复现"，也让验收测试可以不依赖 GUI 直接跑。

**半径滑块上限跟随图片尺寸。** 换图后把半径滑块的 `to` 调整为长边的一半，避免沿用上一张图的量级导致"必然检不出"。

**参数读取时夹紧下界。** OpenCV 要求 `dp`、`minDist`、`param1`、`param2` 为正数，滑块的 `from` 可能被拖到 0，因此在组装 `CircleParams` 时统一 `max(1, value)`，把非法组合挡在调用之前。

## Risks / Trade-offs

- [dp 过大或半径范围过宽时，单次检测耗时上升，滑块可能出现卡顿] → 用 150 ms 防抖限制调用频率；实拍图（385×760、520×520）单次检测在 100 ms 内，交互可接受。
- [实拍图背景复杂时会出现假圆，例如硬币边缘的齿纹被识别成更小的圆] → 通过 `minDist` 抑制同圆重复检出、通过半径区间排除量级不符的圆；参数预设已按两张样例图固化。
- [tkinter 在 macOS 上的 Retina 缩放与 Windows 不一致] → 画布只做等比缩放，不依赖物理像素；导出始终使用原图坐标，缩放差异不影响结果。
- [OpenCV 版本差异可能导致同一参数的检出数量变化] → `requirements.txt` 限定 `opencv-python>=4.8`，测试用固定断言守住两张样例图的数量与半径区间。
